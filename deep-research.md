# Local Deep Research System

**Version:** 0.1

## Goals

Build a completely local (or mostly local) research assistant capable of:

* Performing iterative web research
* Evaluating source quality
* Collecting evidence before answering
* Producing traceable, cited responses
* Explaining *why* it reached a conclusion
* Allowing the user to inspect every stage

This is intended to behave more like a junior research analyst than a chatbot.

---

# Design Philosophy

Separate responsibilities.

The LLM should **not** be responsible for everything.

Instead, create a pipeline of specialized components.

```text
Question
    ↓
Planning
    ↓
Research
    ↓
Evidence Collection
    ↓
Evidence Evaluation
    ↓
Reasoning
    ↓
Answer Generation
```

---

# Guiding Principles

## Evidence First

Never answer directly from search results.

Always answer from collected evidence.

---

## Sources are Scored, Never Trusted

No source is inherently true.

Every source receives a confidence score.

Example factors:

* domain reputation
* author reputation
* citations
* publication date
* topic expertise
* corroboration

---

## Every Claim Has Evidence

Every statement generated by the LLM should be traceable.

Example:

```
Claim
    ↓
Evidence ID 17
    ↓
Source URL
    ↓
Quoted passage
```

This creates an evidence graph rather than opaque text generation.

# Major Components

## 1. Planner

Purpose:

Convert a broad question into a research plan.

Example

```
How does fusion power work?

↓

Need:

history
physics
current reactors
commercial efforts
major challenges
```

---

## 2. Query Generator

Produces multiple search queries.

Instead of

```
fusion
```

Generate

```
fusion reactor history

tokamak engineering

ITER progress

stellarator comparison

commercial fusion startups
```

---

## 3. Search Layer

Possible implementations

* SearXNG
* Brave Search
* Local search index
* Enterprise search

Responsibilities

* retrieve candidates
* deduplicate
* basic ranking

---

## 4. Fetch Layer

Downloads pages.

Extracts

* article
* title
* author
* date
* body
* metadata

Ignore

* ads
* navigation
* comments
* unrelated page content

---

## 5. Source Quality Engine

Produces a quality score.

Example

```
Government
+25

University
+20

Official documentation
+20

Peer reviewed
+20

Named author
+10

Recent publication
+5

No citations
-15

Spam indicators
-40
```

---

## 6. Knowledge Store

Stores

```
documents

chunks

embeddings

metadata

quality score

crawl date

topic tags
```

---

## 7. Retrieval Engine

Hybrid retrieval

```
BM25

+

Vector Search

+

Metadata Filters
```

This generally performs better than embeddings alone.

---

## 8. Re-ranking

Given

Top 100 chunks

Return

Best 10

using a cross-encoder reranker.

---

## 9. Evidence Notebook

This is probably the most important subsystem.

Every useful piece of information becomes an evidence object.

```
Evidence

ID

Source

Author

Date

Quote

Confidence

Related Claims

Related Topics
```

---

## 10. Claim Generator

Creates answers only from notebook evidence.

Not from memory.

---

## 11. Verification

Before returning:

Check

* unsupported claims
* contradictory evidence
* stale sources
* duplicate citations
* missing references

---

# Trust Model

No binary trust.

Instead:

```
Domain Score

+

Evidence Quality

+

Cross Source Agreement

+

Freshness

+

Primary Source Bonus

=

Confidence
```
